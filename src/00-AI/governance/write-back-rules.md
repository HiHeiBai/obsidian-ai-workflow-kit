# Write-back Rules

AI 写入前先判断内容类型，再写到对应位置。

下表为公开版默认路径。已有 vault 的目录或字段映射只在本地扩展定义，并引用本页；不要为路径差异复制整套规则。managed core 文件只在公开源码修改，再通过 `shared-core` 导入；用户资料和经验使用用户所有的目录。

| 内容类型 | 写回位置 | 长期价值判断 |
|---|---|---|
| 项目长期状态 | 既有项目事实文档（如 `10-Projects/<project>/current-state.md`）；桥接卡仅保存经核验的当前摘要。没有独立状态文档的小项目可直接以桥接卡为事实源 | 下次接手必须知道 |
| 稳定决策 | `10-Projects/<project>/decisions.md` | 已确认且会影响后续行动 |
| 临时交接 | `01-Inbox/agent-handoffs/` | 只服务下一次接续 |
| 排队、跨会话或阻塞任务 | `01-Inbox/tasks/` | 当前对话无法闭环，并且需要明确下一步 |
| 外部资料分析 | `40-ExternalSources/` | 有来源、有摘要、有可用结论 |
| 可复用经验 | `20-SharedAssets/01-user-assets/` 或问题知识卡 | 未来多个任务会重复用；用户资产不写入 managed core |
| 问题/事故经验 | 用 `00-AI/templates/TPL-incident-experience-card.md` 新建后放到项目或 `20-SharedAssets/01-user-assets/` | 下次能避免失败、误判、返工或工具异常 |
| 召回入口 | 私人经验链接进入用户所有的项目、主题或本地召回页；通用 `00-AI/recall/` 在公开源码维护 | 能告诉 AI 什么任务先读什么 |
| 模板 | 用户模板进入 `20-SharedAssets/01-user-assets/` 或本地扩展；通用 `00-AI/templates/` 在公开源码维护 | 会重复创建同类页面 |

外部资料的原文、提炼与产出分层见 `00-AI/pipeline/source-to-knowledge-workflow.md`；已收藏原文不会因完成提炼自动归档。

交接卡不是任务完成回执。只有确实需要另一个窗口或 Agent 接手时才创建；当前对话已经闭环、仅有文件变化或只需更新项目状态时，不建交接卡。

## 桥接卡与交接卡：只保存当前摘要

新卡和本次改写的旧卡标记 `record_format: compact-v1`；不为补标记批量改动无关旧卡。

- 桥接卡回答项目现在怎样、哪些决策仍有效、能做什么、下一步做什么。交接卡只服务明确的接手；不是任务完成回执或测试报告。
- 先更新既有项目事实文档，再按变化替换卡中对应段落；不按日期追加流水账，不重复抄录测试数字和实现清单。状态、决策、边界、证据、下一步均无变化时不写，也不只刷新日期。
- 桥接卡“当前状态”最多 5 点，“有效决策”最多 5 点。正文只有一个“下一步”区块，用 `首要动作：`（英文 `Primary action:`）写 1 个动作，可列最多 2 项必要依赖。frontmatter `next_action` 必须与首要动作完全一致，它只是字段镜像，不是另一套计划。
- 交接卡只保留接手目标、必要的当前结果、一个首要动作及最多 2 项依赖、阻塞与操作边界、关键证据入口。已有同一次接手的卡片逐段替换，不反复新建进度卡。
- `last_verified` 只在实际核验项目事实后更新。创建卡片、格式整理或规则迁移不算事实核验；未核验则留空并写清待核验内容。

桥接卡与事实文档冲突时先核验，不能按较新的编辑日期判断业务状态；`next_review` 到期也不能直接顺延或关闭任务。项目登记、关注页和索引只维护导航或已确认的优先级，Base 从事实页展示字段，不另存一份动态状态。

| 卡片 | 正文 Unicode 字符上限 | 非空行上限 |
|---|---:|---:|
| 项目桥接卡 | 3000 | 120 |
| Agent 交接卡 | 1800 | 80 |

计量时移除文件开头的 YAML frontmatter，换行统一为 LF，剩余正文按 Unicode 字符计数，包含标题、标点、空白和链接。非空行指去掉首尾空白后仍有内容的行。这不是字数或 Token 限额；字符和行数必须同时满足。frontmatter 仅保存简短字段，不能用来转存正文。

超限是内容分流信号：先把详细实现过程、旧决策、逐次测试输出保存到既有项目日志、验收文档或可追溯历史，再在卡中留下定位链接。确认历史可访问后，才从当前摘要移出过时内容；不能只截断或丢弃信息，也不为每次小修改另建归档文件。

未解决阻塞、操作授权边界和关键证据必须保留。分流后仍不可压缩时，在 frontmatter 的短字段 `compact_exception` 中写清例外原因及复核条件；例外只用于人工复核，检查仍应报告超限，不能静默通过。

写后执行只读检查：`python3 00-AI/scripts/kb.py check-record <card.md>`。长度检查通过不代表内容正确，还须确认首要动作一致、证据能定位、未丢失阻塞与授权边界。

## 写入格式

- 事实：写清来源。
- 判断：标明是推断还是已验证结论。
- 下一步：写成可执行动作。
- 风险：写清楚不能做什么。
- 问题/事故：必须写清触发条件、根因、处理动作、验证方式和禁止事项。
- 任务卡：必须写清 `status / project / priority / updated / next_action`，由任务字段完成分流。

## 删除规则

AI 默认不删除长期内容。已有删除或合并授权时，执行前明确以下信息并保留必要恢复入口，无需重复索要同一授权：

- 删除对象。
- 删除原因。
- 是否有替代入口。
- 是否会影响召回。
