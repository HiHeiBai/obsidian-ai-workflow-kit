# Maintenance Loop

知识库维护不是整理更多目录，而是让 AI 能继续找得到、信得过、用得上。

本页用于用户安排的维护任务；日常写卡按写回规则做定向检查，不把完整巡检附加到每个任务。`shared-core` 的公共健康检查只覆盖受管核心，已有 vault 的私人路径、项目和扩展由其本地巡检覆盖。

## 每周轻量维护

1. 运行：

```bash
python3 90-系统/脚本/kb.py health-check
```

2. 检查 `01-收件箱/` 是否有长期滞留。
3. 检查项目桥接卡是否仍然反映当前状态。
4. 检查 `project_entry` 项目入口、任务卡和资料卡是否仍出现在对应 Base；不要把 Base 当作唯一事实源。
5. 检查高价值问答是否已沉淀成经验资产。
6. 检查召回地图是否能回答“这个任务开始前读什么”。

## 每月维护

- 合并重复资料卡。
- 标注过时结论。
- 检查本地扩展是否又复制了共享规则；通用改进回到公开源码，本地仅保留差异和引用。
- 把高复用经验挂到用户所有的项目、主题或本地召回入口；公共召回地图只维护通用路由，需在公开源码更新后导入。
- 清理没有来源、没有结论、没有使用场景的临时内容。
