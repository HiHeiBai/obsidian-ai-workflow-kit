# Startup Contract

已知项目或文件时直接读取相关上下文；需要定位入口时再读 `00-入口/开始这里.md`，按任务逐步补充。

当前对话能完成的任务直接执行，不先创建任务卡。只有排队、跨会话、阻塞或明确协调的工作才进入 `01-收件箱/任务/`。

先读目标和适用的项目约定。导航定位到事实源后，不沿所有链接继续加载；本会话中已读且仍有效的内容可复用。

## 开工判断

明确任务、已有授权和可检查结果后直接执行。只有缺失信息会实质改变结果、风险或授权范围时才询问；已授权事项不重复确认。不要求固定开工回执。

## 按需上下文

| 任务 | 需要对应信息时读取 |
|---|---|
| 整理本机资料 | `20-资料/处理流程/README.md`、`20-资料/处理流程/本机资料进入流程.md` |
| 接手项目 | 项目桥接卡、`current-state.md`、`decisions.md` |
| 资料整理 | `20-资料/处理流程/README.md`、资料分析模板 |
| 经验沉淀 | 经验资产化机制、问题知识卡模板 |
| 维护知识库 | 巡检清单、召回地图、健康检查结果 |
| 接续本地任务 | 对应任务卡、项目桥接卡、验收证据 |

跨文件改动按影响范围补充契约、调用处和验证入口；只有版本冲突或需要历史依据时才读对应历史，历史记录不代替当前事实。上下文足够即可执行。

## 执行与交付

查看、解释和评估默认只读；用户要求修改或实施后，完成授权范围内的实现与验证。沿用现有结构，保留已有改动，不附带无关重构或新流程。

按任务复杂度说明结果、必要依据、验证与实际限制，不套固定段落或条数。实际写入长期记忆时说明文件位置。知识写入、合并或迁移的检查见 `90-系统/规则/写入审查门槛.md`。

## 禁止行为

- 不在没有任务目标时全库扫描。
- 不把 Inbox 当长期存储。
- 不把私人凭据、账号信息、Token、Cookie 写入 vault。
- 不用没有来源的推测覆盖已有事实。
- 需要专业视角时，直接写明检查角度和验收标准。
