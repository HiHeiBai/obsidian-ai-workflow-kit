# START HERE

语言：中文

> 给任何新窗口 / 新 Agent：先读完本文件，就知道该读什么、写到哪里、不能做什么。

## 一句开工指令

```text
你是知识库维护 Agent，请阅读当前 vault 的 00-入口/开始这里.md，并按里面的开工流程执行。
```

如果 AI 不是从 vault 根目录启动，把 vault 路径一并发给它：

```text
你是知识库维护 Agent。这个 Obsidian vault 的根目录是：<your-vault-path>。请先读取该目录下的 00-入口/开始这里.md，并按里面的开工流程执行。
```

## 正确触发后的回执

AI 读完本文件后，应先用下面格式回执，而不是立刻扫描整个 vault：

```text
已读取：00-入口/开始这里.md
任务类型：<文档整理与分类建议 / 整理本机资料 / 接手项目 / 整理外部资料 / 沉淀经验 / 维护知识库 / 写交接 / 待确认>
下一步先读：<具体文件>
结果写回：<具体目录或文件>
不会做：<本轮明确不做的事>
```

## 开工三步

> 默认直接执行：当前对话能完成的任务不创建任务卡。只有任务需要排队、跨会话继续、等待外部条件或明确协调多个执行者时，才写入 `01-收件箱/任务/`。

### 第 1 步：确认任务类型

| 任务类型 | 先读 |
|---|---|
| 文档整理与分类建议 | `首页.md`、`20-资料/处理流程/README.md`、`20-资料/处理流程/本机资料进入流程.md` |
| 整理本机资料 | `20-资料/处理流程/README.md`、`20-资料/处理流程/本机资料进入流程.md` |
| 接手项目 | `10-项目/<项目>/BRIDGE-*.md` |
| 整理外部资料 | `20-资料/处理流程/README.md`、`90-系统/模板/TPL-资料分析卡.md` |
| 沉淀经验 | `30-经验资产/02-通用模块/项目经验沉淀机制-v1.md`、`90-系统/模板/TPL-问题知识卡-经验资产卡.md` |
| 复盘问题/事故 | `30-经验资产/02-通用模块/项目经验沉淀机制-v1.md`、`90-系统/模板/TPL-问题事故经验卡.md` |
| 维护知识库 | `90-系统/规则/维护循环.md`、`30-经验资产/02-通用模块/知识库健康检查清单-v1.md` |
| 写交接 | `90-系统/模板/TPL-Agent交接卡.md` |
| 接续本地任务 | `01-收件箱/任务/<task>.md`、相关项目桥接卡 |

### 第 2 步：只加载必要上下文

- 先读 `首页.md` 和本文件。
- 需要治理规则时读 `90-系统/规则/README.md`。
- 需要召回规则时读 `90-系统/召回/任务上下文地图.md`。
- 有项目任务时，只读对应项目桥接卡。
- 不要一上来扫描整个 vault。
- 用户要“整理文档”“分类建议”“知识库怎么放”时，先清点用户给出的范围；如果没有给范围，只看 vault 顶层目录、README、索引和少量文件名，输出整理建议。不要默认创建映射、召回规则或新目录。

### 文档整理与分类建议的输出

先输出整理建议，不要先写文件：

```text
现有内容判断：<当前资料主要是什么>
建议分类：
- <资料/目录> -> <建议放置位置>，原因：<一句话>
建议先做：
1. <最小可执行动作>
暂不处理：<不确定或需要用户确认的内容>
```

### 第 3 步：按写回位置保存结果

| 内容 | 写到哪里 |
|---|---|
| 临时交接 | `01-收件箱/Agent交接/` |
| 排队、跨会话或阻塞任务 | `01-收件箱/任务/` |
| 外部资料分析 | `20-资料/01-示例/` 或对应主题目录 |
| 项目状态 | 对应项目桥接卡 |
| 复用经验 | `30-经验资产/06-本地经验/` |
| 问题/事故经验 | 复制 `90-系统/模板/TPL-问题事故经验卡.md` 后写入对应项目或共享资产 |
| 召回规则 | `90-系统/召回/` |
| 标准模板 | `90-系统/模板/` |

## 禁止事项

- 不保存密钥、Token、Cookie、验证码、私钥和账号凭据。
- 不把完整聊天记录当长期记忆。
- 不直接复制第三方原文全文。
- 不把 Inbox 当长期目录。
- 不在没有明确任务时批量重构目录。
- 需要专业检查时，直接说明本轮检查视角和验收标准。

## 任务结束前检查

- 说明实际改了什么。
- 说明为什么这样改。
- 说明验证了什么。
- 说明是否写入记忆；如果没有，说明未写入记忆。
